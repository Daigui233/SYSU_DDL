## 一、整体架构

路径规划链路分为**四层流水线**，逐层把视觉感知结果转化为下发给 TC264D 下位机的最终控制帧：

```
融合视频帧（shm_ar_video）
       │
       ▼
┌────────────────────────────────────────────┐
│  第0层：分割中线提取  seg_func.py          │
│  语义分割 → 道路掩码 → 中线提取 → track_error │
└──────────────────┬─────────────────────────┘
                   │ perception
                   ▼
┌────────────────────────────────────────────┐
│  第1层：任务状态机  control_task_state_machine.py │
│  感知 + 检测结果 → 任务状态 + 规划意图 + 目标速度  │
└──────────────────┬─────────────────────────┘
                   │ task_decision
                   ▼
┌────────────────────────────────────────────┐
│  第2层：局部规划器  control_local_planner.py │
│  中线 + 任务意图 → 目标路径 + final_track_error │
└──────────────────┬─────────────────────────┘
                   │ plan_result
                   ▼
┌────────────────────────────────────────────┐
│  第3层：控制仲裁器  control_arbitrator.py   │
│  final_track_error → 缩放/死区/限幅 → TC264D │
└──────────────────┬─────────────────────────┘
                   │ 串口帧
                   ▼
            TC264D 下位机
```

每一层都有独立的调车参数区，参数修改后重启 `ar_receiver.py` 生效。

> 注：`control_states.py` 是纯契约文件，定义状态枚举和 RK↔TC264D 状态映射表，不含任何逻辑 —— 不参与路径规划，下文不再赘述。

## 二、第0层：分割中线提取 (`infer_wrap/base/seg_func.py`)

这是整个路径规划的**源头**，输入是神经网络语义分割输出（分类图，256×256），输出是 `track_error`（像素误差）和 `mid_points`（中线点序列）。

### 2.1 核心函数：`extract_centerline_info(seg_map, frame)`

```python
返回: (visualization_frame, centerline_info_dict)
```

### 2.2 处理流程

#### 步骤1：分类图转换 `_to_class_map(seg_map)`
- 输入支持多种格式（H×W 单通道、C×H×W 多通道、H×W×C 多通道）
- 对多通道做 **argmax** 得到每个像素的类别索引
- 对道路类别通道做 `-0.10` 的微偏置（softmax 前弱化道路置信度，减少过分割）
- 缩小到原图分辨率（INTER_NEAREST）

#### 步骤2：原始道路掩码生成 `_make_raw_mask(class_map)`
1. 提取 `ROAD_CLASS_ID=1` 的二值掩码
2. **裁剪顶部 34%**（`TOP_CROP_RATIO=0.34`）：避免远景和天空噪声影响道路检测
3. **形态学处理**：
   - `MORPH_CLOSE`（核 5×5）：先膨胀后腐蚀，连接道路内部断裂
   - `MORPH_OPEN`（核 3×3）：先腐蚀后膨胀，去除孤立噪点

#### 步骤3：连通分量选择 `_select_road(mask)`
- 使用 8-邻接连通分量分析
- 对每个连通区域计算评分函数：

  ```
  score = area_score × 3.0 + bottom_contact × 1.5 + center_score × 0.6
  ```

  其中：
  - `area_score`：面积 / (H×W) —— 面积权重最高
  - `bottom_contact`：组件底部72%~100% 区域的填充率 —— 画面下方（近处）有大面积道路的组件更优先
  - `center_score`：组件底部中心偏离图像中心的归一化距离 —— 居中道路优先

- 保留评分最高的 **前2个** 连通区域（`MAX_COMPONENTS=2`），用于后续分支检测
- 过滤最小面积 `MIN_COMPONENT_AREA_RATIO=0.0015`（总面积千分之1.5）

#### 步骤4：掩码稳定性过滤 `_stable_mask(mask, valid, raw_ratio)`
- **质量检查** `_quality()`：
  - 道路比例 `< MIN_ROAD_RATIO(0.001)` → 太小，丢弃
  - 道路比例 `> MAX_ROAD_RATIO(0.60)` → 可能大面积误分割，丢弃
  - 原始道路比例 `> MAX_RAW_ROAD_RATIO(0.86)` → 几乎全画面被识别为路，丢弃

- **帧间跳变检测**：
  - 计算当前掩码与上一帧的 IoU
  - 若面积变化超过 25% **且** IoU < 0.18，判定为"跳变"，丢弃

- **HOLD兜底机制**：
  - 若当前掩码不通过质量检查，但有上一帧的有效掩码且年龄 < 0.5s
  - 则继续使用上一帧掩码，标记 `held=True`，防止短时抖动

- **历史掩码投票**：
  - 保留最近 4 个非 HOLD 帧的掩码
  - 若 >= 2 帧可用，对累积掩码做多数投票（≥ 50% 的像素保留）
  - 用于过滤偶尔的误分割波动

#### 步骤5：中线构建 `_build_midline(mask)`
这是**核心路径生成算法**：

1. **底部锚点**：
   - 取画面最后一行道路像素的宽度中点作为 `bottom_anchor_x`
   - 与上一帧底部锚点 EMA 混合（α=0.20），防止底部跳动

2. **自底向上逐行扫描**（步长 `SCAN_STEP=8` 像素）：
   - 对每一行，搜索当前行的所有连通段（宽度 ≥ `MIN_SEGMENT_WIDTH=12`）
   - 对每个连通段计算得分：

     ```
     best_row_center_score = width × 2.0 - |cx - ref_x| × 2.2 - |cx - prev_x| × 1.2
     ```

     含义：
     - **宽度优先**（×2.0）：选择道路更宽的方向（更可能是主路）
     - **偏离图像中心惩罚**（×2.2）：防止中线跑到画面边缘
     - **连续性惩罚**（×1.2）：与上一选中行中心差距大的候选被抑制

   - 选取得分最高的连通段中心作为该行中线点
   - `ref_x` 动态更新为该行选中的中心，确保连续性
   - 连续 4 行没有找到有效中心 → 停止扫描

3. **历史平滑**：
   - 当前中线点与上一帧对应位置做 EMA 混合：

     ```
     pw = 0.25 + 0.45 × bottom_weight
     cx = (1-pw) × x_new + pw × x_prev
     ```

     近处点（bottom_weight 大）更依赖历史，远处点更相信当前检测

4. **多项式拟合平滑** `_fit_midline(points, w)`：
   - < 8 个点：1 次多项式（直线拟合）
   - ≥ 8 个点：2 次多项式（二次曲线拟合）
   - 拟合后做 55% 原始值 + 45% 拟合值的混合（减少过拟合）

#### 步骤6：加权控制中心 `_weighted_control_center(points, h, w)`
计算最终 `track_error` 的**核心创新**：不再是只看车头底部几行，而是用整条中线加权合成：

```python
for (x, y) in mid_points:
    if y < half_h:
        weight = far_weight  # CONTROL_CENTER_FAR_WEIGHT_RATIO × h
    else:
        weight = max(CONTROL_CENTER_NEAR_MIN_WEIGHT, h - y)

    control_sum += x × weight
    control_weight += weight

control_center_x = control_sum / control_weight
track_error = control_center_x - image_center_x
```

- **远处高权重**（画面上半部，`far_weight = 0.50 × h`）：让弯道更早参与转向 —— **前瞻效果**
- **近处低权重**（画面下半部，权重从远到近线性增加）：确保车身前方贴合当前路面
- 远处固定权重 + 近处递变权重的设计避免了对远处不稳定中线的盲目信赖

#### 步骤7：track_error 平滑
```python
track_error = 0.70 × prev_track_error + 0.30 × raw_error
```
使用中值响应的一阶低通滤波器（EMA），抑制逐帧噪声。

## 三、第1层：任务状态机 (`control_task_state_machine.py`)

### 3.1 状态机总览

```
                        ┌──────────────┐
         ┌─────────────►│ NORMAL_TRACK │◄──────────────┐
         │              └──────┬───────┘               │
         │                     │                        │
         │         ┌───────────┼────────────┐          │
         │         ▼           ▼            ▼          │
         │  ┌──────────┐ ┌──────────┐ ┌────────────┐  │
         │  │AVOID_    │ │COLLECT_  │ │AVOID_STONE │  │
         │  │HUMAN     │ │GOLD      │ │(分岔)      │  │
         │  └──────────┘ └──────────┘ └────────────┘  │
         │                                             │
         ▼                                             │
  ┌──────────────┐                                    │
  │ RECOVER_LINE │ ───────────► (超时3s)              │
  └──────────────┘            ┌─────────────────────┐  │
                              │LINE_LOSS_SAFE_STOP  │  │
                              └─────────────────────┘  │
                                                       │
  ┌────────────────────┐                               │
  │TRAFFIC_LIGHT_STOP  │                               │
  └────────────────────┘                               │
  ┌────────────────────┐                               │
  │ENDSIGN_STOP        │                               │
  └────────────────────┘                               │
```

### 3.2 状态优先级

检测规则按以下优先级执行（高优先级先检查）：

| 优先级 | 状态 | 触发条件 | 退出条件 |
|--------|------|---------|---------|
| P0 | ENDSIGN_STOP | 裁判系统：终点牌丢失 | 不退出（比赛结束） |
| P0 | TRAFFIC_LIGHT_STOP | 裁判系统/视觉：红灯 | 变绿后回 NORMAL_TRACK |
| P1 | LINE_LOSS_SAFE_STOP | 中线连续丢失 ≥ 3s | 重新检测到有效中线 |
| P2 | RECOVER_LINE | 中线短暂丢失 < 3s | 重新检测到有效中线 |
| P3 | AVOID_HUMAN | 近处检测到人 | 人消失且超过 HOLD TTL |
| P3 | AVOID_STONE | 近处检测到石头 | 石头消失 |
| P3 | AVOID_CAR | 近处/前方检测到车 | 车消失 |
| P3 | COLLECT_GOLD | 近处检测到金币 | 金币消失或不可达 |
| P5 | NORMAL_TRACK | 默认（无特殊目标） | — |

### 3.3 感知质量评估 `_segmentation_quality()`

在状态机决策前，先评估分割结果是否可用：

```python
条件检查:
├── MAX_SEGMENTATION_AGE = 0.80s  → 分割结果年龄不能太老
├── line_valid                    → track_error 不为空且 line_valid 为 True
├── MIN_ROAD_RATIO = 0.001        → 道路面积不能太小
├── MAX_ROAD_RATIO = 0.60         → 道路面积不能太大（误把背景当路）
├── REQUIRE_ROAD_VALID = True     → road_valid 必须为 True
├── REQUIRE_MIDLINE_VALID = True  → midline_valid 必须为 True
├── VALID_ROAD_STATES = (OK, HOLD) → road_state 只能是 OK 或 HOLD
└── VALID_MIDLINE_STATES = (OK, HOLD) → midline_state 只能是 OK 或 HOLD
```

### 3.4 近处目标筛选 `_near_detection_candidates()`

只处理**画面下方 40% 内且靠近中线**的检测目标，过滤逻辑：

1. **底部区域要求**：检测框底边 `bottom >= frame_h × (1 - 0.40)`（即进入画面下方 40%）
2. **侧向距离限制**：目标中心偏离中线的距离 ≤ `max(NEAR_CENTER_LATERAL_RATIO×W, NEAR_BOX_LATERAL_GAIN×box_w, 52px)`
3. **类别特定门限**：
   - human: `score ≥ 0.35`
   - stone: `score ≥ 0.35` 且 `area_ratio ≥ 0.0005`
   - car: `score ≥ 0.35`（前方中心检测器额外过滤）
   - gold: `score ≥ 0.35` 且 `area_ratio ≥ 0.001` 且偏离中线 < 36% 宽度 且偏离当前误差 < 42% 宽度
4. **排序**：按 `(底部比例, 侧向距离倒数, 类别偏置, 置信度×0.01)` 降序

### 3.5 Car 专用检测器 `_front_center_detection()`

Car 比通用近处检测多一层过滤：只处理画面**下方 35% 区域**的目标，且对 box_width 更敏感。用复合评分排序：

```
rank = score + area_ratio × 6.0 - lateral_dist / W
```

面积权重（6.0）很高，相当于只有大（近）的 car 才触发避车。

### 3.6 人类保持机制（HOLD TTL）

- 检测到人后，即使下一帧短暂消失，在 0.8s（`HUMAN_HOLD_TTL`）内仍维持 AVOID_HUMAN 状态
- 防止检测框抖动导致状态反复切换

### 3.7 中线丢失处理

```
中线有效                    → NORMAL_TRACK (或其他正常状态)
中线丢失 < 3.0s             → RECOVER_LINE (保持上一帧误差 × 指数衰减)
中线丢失 ≥ 3.0s             → LINE_LOSS_SAFE_STOP (target_speed=0, track_error=0)
重新找到中线               → 下一帧立即回到 NORMAL_TRACK
```

## 四、第2层：局部规划器 (`control_local_planner.py`)

### 4.1 规划器接口

```python
plan_result = planner.plan(perception, task_decision, now)
# 返回: {
#   final_track_error: 最终转向误差(px)
#   target_path: [(x,y), ...]  紫色规划路径
#   target_x: 前瞻点x坐标
#   planner_reason: 规划原因
#   ...
# }
```

### 4.2 各状态规划策略

#### 4.2.1 NORMAL_TRACK — 赛道中心巡线

```
path_offset = 0.0
target_path = _build_target_path(segmentation, 0.0)
final_error = 分割中线在前瞻点的误差
```

最简单的模式：目标路径 = 红色分割中线。

#### 4.2.2 AVOID_HUMAN / AVOID_CAR — 绕障偏移

**核心算法**：在基础中线上叠加横向偏移

```python
# 1. 确定偏移方向（左右）
avoid_side = _choose_avoid_side(segmentation, target, prefer_away, "human/car")

# 2. 计算偏移量
path_offset = side_sign × max(HUMAN_AVOID_OFFSET, bbox_width × AVOID_BOX_WIDTH_GAIN)
# 人: 基础75px, 车: 基础55px, 两者都随bbox宽度线性放大

# 3. 构建偏移目标路径
target_path = _build_target_path(segmentation, path_offset)
# 在中线的每个点上叠加 offset × bias_gain(y)
```

**偏移方向选择** `_choose_avoid_side()`：

1. **初始偏好**：
   - Human (`prefer_away=True`)：优先选择目标中心反方向（远离人）
   - Car (`prefer_away=False`)：优先选择道路更宽的一侧

2. **道路可通行性评估** `_road_free_side()`：
   - 在目标 obstacle 下方 ROI 区域内统计左右两侧的 road mask 像素数
   - 若左右差异 < `min(20px, 5%总像素)`，视为平衡，不强制换侧
   - 否则选择 road mask 像素更多的一侧（路更宽）

3. **方向滞回** `_apply_avoid_side_hysteresis()`：
   - 同一类别障碍物的避障方向在 **0.8s** 内保持稳定
   - 只有目标中心越过中线超过 **36px** 时才允许换侧
   - 防止检测框在中线附近抖动导致左右摇摆

**偏移量自适应放大**：

```
avoid_offset = max(基础偏置, bbox_width × 0.35)
```
障碍框越大（越近），绕得越远。

#### 4.2.3 COLLECT_GOLD — 金币靠近

```python
target_error = 金币中心x - 画面中心x
bias = clamp((target_error - base_error) × 0.45, -75px, 75px)
path_offset = bias
```

只偏移目标线，不完全脱离中线（`GOLD_BIAS_GAIN=0.45` 表示 45% 偏向金币、55% 保持原中线方向）。

防止策略：
- 偏离中线超过 36% 宽度的金币不捡（太偏）
- 偏离当前误差超过 42% 宽度的金币不捡（路径代价太高）
- 最大单帧偏置 75px（防止突然猛拐）

#### 4.2.4 AVOID_STONE — 分岔路线选择

石头通常放在道路**分岔口**（如Y字路口），需要选择左侧还是右侧的路线。这是一个**二分岔路径规划器**：

**步骤1：构建分岔候选** `_build_stone_branch_candidates()`
- 对每个中线采样点，搜索该行 mask 中的所有连通段
- 若某行有 ≥ 2 个连通段，该行即为"分岔行"
- 左侧候选：每行取最左侧连通段中心
- 右侧候选：每行取最右侧连通段中心
- 至少 `STONE_BRANCH_MIN_SPLIT_ROWS=4` 行同时分岔才算有效分岔

**步骤2：路径选择** `_select_stone_branch()`
- 两条候选路径按 `continuity_cost`（与当前误差的接近程度）排序
- 更接近当前误差的是 outer（外圈/主路），差距大的是 inner（内圈/岔路）
- **关键决策**：检查石头碰撞线
  - `_stone_hits_path()`：石头的横向位置是否落在 outer 路径的走廊内（走廊宽度 = `max(8%×W, 75%×box_w, 32px)`）
  - 若石头在 outer 上 → **选择 inner（岔路）**
  - 若石头不在 outer 上 → **保持 outer（主路）**

#### 4.2.5 RECOVER_LINE — 丢线保持

```python
decay = max(0.0, 1.0 - age / RECOVER_DECAY_SECONDS)  # age在3秒内从1→0线性衰减
final_error = last_valid_track_error × decay  # last_valid_track_error是上一帧有效误差
```

在 3.0s 内线性衰减到 0，而不是突然归零，让车在丢线瞬间继续朝原方向走。

#### 4.2.6 SAFE_STOP — 停车

```python
final_error = None  → target_speed=0, track_error=0
```

### 4.3 目标路径生成 `_build_target_path()`

这是**紫色规划线**的生成算法：

```python
for (x_raw, y) in sampled_mid_points:
    # 1. 计算该y位置的偏移增益
    bias_gain = _path_bias_gain(y, frame_h)
    #    画面底部近处：bias_gain = 0.28 (PATH_NEAR_BIAS_GAIN)，不完全贴死红线
    #    画面中部过渡：用 smoothstep 从 0.28 过渡到 1.0
    #    画面远处：bias_gain ≈ 1.0，完整应用偏移

    # 2. 偏移原始中线
    shifted_x = mid_x + path_offset × bias_gain

    # 3. 裁剪到 road_mask 边界内
    clamped_x = clamp(shifted_x, road_left + 8px, road_right - 8px)
```

**偏移增益平滑过渡**（smoothstep）：
```
t = (near_y - y) / (near_y - full_y)          # y从底部往上的归一化进度
smooth = t² × (3 - 2t)                         # Hermite smoothstep
gain = near_gain + (1 - near_gain) × smooth    # 0.28 → 1.0
```

- `PATH_NEAR_ANCHOR_Y_RATIO = 0.94`（近处锚点，y 在画面 94% 高度）
- `PATH_FULL_BIAS_Y_RATIO = 0.46`（远处完整偏移点）

设计意图：近处靠近车身时不完全偏移（车来不及转弯），到远处才完整偏到障碍物旁边。

### 4.4 前瞻点误差计算 `_path_error_at_lookahead()`

```python
lookahead_y = frame_h × CONTROL_LOOKAHEAD_Y_RATIO  # 0.58
target_x = 紫色规划线在 lookahead_y 处的 x 坐标
final_track_error = target_x - center_x
```

不取最近的路径点，而是在画面 **58% 高度**处取前瞻点，相当于看向前方约半幅画面的位置。

### 4.5 final_track_error 平滑 `_smooth_final_error()`

```python
# 1. EMA 平滑
smoothed = previous + (target_error - previous) × 0.45  # smooth alpha

# 2. 逐帧变化限制
max_step = 28px
smoothed = previous + clamp(smoothed - previous, -28, 28)  # 防止左右瞬移

# 3. 全局限幅
smoothed = clamp(smoothed, -max_track_error, +max_track_error)
# max_track_error = min(320px auto, 固定上限)
```

### 4.6 反向推算有效偏移量 `_effective_path_offset_for_error()`

当平滑后的 final_error 和原始 path_offset 不一致时，反算实际生效的偏移量，用于绘制正确的目标路径：

```
effective_offset = (target_x - base_x_at_lookahead) / gain_at_lookahead
clamp(effective_offset, -|desired_offset|, +|desired_offset|)
```

## 五、第3层：控制仲裁器 (`control_arbitrator.py`)

### 5.1 视觉误差整形 `_shape_vision_track_error()`

这不是简单的线性缩放，而是一个**非线性误差整形管道**：

```
final_track_error (px)
       │
       ▼
  scale_fixed × state_scale (分状态缩放)
       │
       ▼
  curve_boost: 大弯非线性增强
       │
       ▼
  deadband: 小误差死区置零
       │
       ▼
  max_abs clamp: 输出限幅
       │
       ▼
  max_step clamp: 逐帧变化限制
       │
       ▼
input_track_error → TC264D
```

#### 分状态缩放表

| 状态 | scale | max_abs | max_step | deadband | curve_start | curve_gain |
|------|-------|---------|----------|----------|-------------|------------|
| NORMAL_TRACK | 0.65 | auto | 22 | 3 | 40 | 0.55 |
| AVOID_STONE | 0.65 | auto | 22 | 3 | 40 | 0.55 |
| RECOVER_LINE | 0.55 | 85 | 8 | 3 | 0 | 0 |
| COLLECT_GOLD | 0.65 | auto | 14 | 2 | 50 | 0.25 |
| AVOID_CAR | 0.90 | auto | 22 | 2 | 60 | 0.20 |
| AVOID_HUMAN | 0.90 | auto | 22 | 2 | 60 | 0.20 |
| TRAFFIC_LIGHT_STOP | 0.0 | 1 | 999 | 0 | 0 | 0 |
| ENDSIGN_STOP | 0.0 | 1 | 999 | 0 | 0 | 0 |

#### 曲线增益 `_apply_curve_boost()`

```
if |raw_error| > curve_start:
    extra = (|raw_error| - curve_start) × curve_gain
    shaped_error += sign(raw_error) × extra
```

**设计意图**：类似 Cardo 的非线性转向增益。小弯时线性缩放（避免抖动），大弯（> 40px）时额外增强（响应更快，避免转向不足）。

#### 自动限幅计算

```python
max_abs = frame_width × 0.50  # 画面宽度的一半
# 640宽 → max 320px,  320宽 → max 160px
```

### 5.2 控制源仲裁

```python
if gamepad_cmd is not None:        # 手柄遥控有效
    使用手柄的控制帧
else:                               # 默认视觉巡线
    使用视觉状态机的控制帧
```

手柄接管只是简单的覆盖，不影响上游的状态机和定位链路。

### 5.3 最终输出结构

```python
{
    "track_error": float,       # 整形后的转向误差 (TC264D输入)
    "target_speed": float,      # 目标速度 (m/s)
    "state_cmd": int,           # TC264D状态码 (1=TRACK, 7=SAFE_STOP等)
    "flags": 0x01,              # 控制标志位
    "state_text": str,          # 调试用的状态文本
}
```

通过串口 `/dev/ttyUSB0` @ 460800 baud 发送给 TC264D。

## 八、参数调优指南

所有调车参数在各文件开头的字典常量区中，修改后重启 `ar_receiver.py` 生效：

| 文件 | 参数区 | 主要内容 |
|------|--------|----------|
| `seg_func.py` | 顶层常量 | TOP_CROP_RATIO, HOLD_SECONDS, 加权权重, 平滑α |
| `control_task_state_machine.py` | `TASK_SPEED_DEFAULTS` | 各状态目标速度 |
| `control_task_state_machine.py` | `TASK_RULE_DEFAULTS` | 检测门限、近处ROI、候选排序权重 |
| `control_task_state_machine.py` | `PERCEPTION_QUALITY_DEFAULTS` | 分割质量门限 |
| `control_local_planner.py` | `PLANNER_DEFAULTS` | 绕障偏置、金币增益、路径平滑、前瞻点 |
| `control_arbitrator.py` | `CONTROL_ERROR_PARAMS` | 分状态缩放、死区、curve boost、步长限制 |

### 常见调车场景

1. **弯道转向不够** → 增大 `control_arbitrator.py` 的 `curve_gain` 或增大 `seg_func.py` 的 `CONTROL_CENTER_FAR_WEIGHT_RATIO`
2. **直道抖动** → 增大 `control_arbitrator.py` 的 `deadband` 或减小 `scale`
3. **障碍物绕行太近** → 增大 `control_local_planner.py` 的 `CAR_AVOID_OFFSET` / `HUMAN_AVOID_OFFSET`
4. **丢线后方向保持不够** → 增大 `RECOVER_DECAY_SECONDS`
5. **目标线摆动太大** → 减小 `FINAL_ERROR_SMOOTH_ALPHA`（更平滑），增大 `MAX_ERROR_STEP_PER_FRAME`（允许更快响应）
6. **分割噪点多** → 先改善模型训练，再调紧 `PERCEPTION_QUALITY_DEFAULTS` 把 `ALLOW_HELD_SEGMENTATION=False`
